## Function Description

Header file path: `"hcomm/hcomm.h"`.

Blocks until communication tasks submitted through an ordinary channel complete, or until the completion records generated by tasks submitted through a **BatchHandle** are available.

The normal overload relies on the temporary workspace provided by `Init`; the batch overload uses the workspace bound by [MakeBatchHandle](./MakeBatchHandle.md) and does not rely on `Init`.

## Function Prototype

Common API:

```cpp
template <pipe_t pipe = PIPE_MTE3>
__aicore__ inline int32_t Drain(AscendC::ChannelHandle channel);
```

Batch API:

```cpp
template <
    pipe_t pipe = PIPE_S,
    typename T,
    typename HandleTraits<T>::ChannelType* = nullptr>
__aicore__ inline int32_t Drain(T& batchHandle);
```

## Parameters

**Table 1** Template parameters

| Parameter | Description |
| --- | --- |
| `pipe` | Pipe used by drain. The default is `PIPE_MTE3` for the common API and `PIPE_S` for the batch API. |
| `T` | Batch handle type, deduced from the `batchHandle` argument. |

**Table 2** API parameters

| Parameter | Input/Output | Description |
| --- | --- | --- |
| `channel` | Input | Communication channel handle used by the common API. |
| `batchHandle` | Input/Output | Single-channel or multi-channel batch handle created by [MakeBatchHandle](./MakeBatchHandle.md), used to wait for the completion records generated by tasks already submitted through this handle. |

## Return Value

**Table 3** Return values

| Return Value | Description |
| --- | --- |
| `0` | Waiting succeeds. |
| `-1` | An argument or **BatchHandle** state is invalid, or the protocol returns a generic failure. |
| `0xFF` | Completion queue polling timed out under the `COMM_PROTOCOL_UB_CTP` protocol. |
| Positive values other than `0xFF` | The completion record reports an error under the `COMM_PROTOCOL_UB_CTP` protocol; the upper 8 bits of the return value are `status`, and the lower 8 bits are `substatus`. |

**Table 4** `status` value description

| `status` Value | Description |
| --- | --- |
| `0x00` | No error. |
| `0x01` | Unsupported opcode. |
| `0x02` | Local operation error. |
| `0x03` | Remote operation error. |
| `0x04` | Transaction retry count exceeded. |
| `0x05` | Transaction ACK timeout. |
| `0x06` | Work request flushed (not an error). |
| Other values | Reserved. |

**Table 5** `substatus` value description

| `status` Value | `substatus` Value | Description |
| --- | --- | --- |
| `0x02` | `0x01` | Local length error. |
| `0x02` | `0x02` | Local access error. |
| `0x02` | `0x03` | Remote response length error. |
| `0x02` | `0x04` | Local data corruption. |
| `0x03` | `0x01` | Remote unsupported request. |
| `0x03` | `0x02` | Remote access aborted. |
| `0x03` | `0x04` | Remote data corruption. |

For other `status` values, `substatus` has no meaning and defaults to `0`.

## Usage Constraints

- The `COMM_PROTOCOL_UB_CTP` and `COMM_PROTOCOL_ROCE` protocols are supported.

**Common API**

- Call `Init` to provide temporary workspace before this API.
- This overload waits for completion records produced by the ordinary `ChannelHandle` workflow.

**Batch API**

- Does not require calling `Init`.
- In multi-channel mode, pass the multi-channel batch handle returned by `MakeBatchHandle` to the batch `Drain`. For logical channel selection, see [GetHandleRef](./GetHandleRef.md).
- Multi-channel batch is supported only by the `COMM_PROTOCOL_UB_CTP` protocol. `COMM_PROTOCOL_ROCE` does not support multi-channel mode.
- Before calling, you must submit all tasks in the current batch through [BatchCommit](./BatchCommit.md). If there are unsubmitted tasks, the call returns `-1`.
- Multiple `BatchCommit` calls can be followed by one batch `Drain`, which waits for all completion records generated by tasks accumulated and submitted through that **BatchHandle**.
- If all submitted tasks use `cqe = 0`, this API returns directly and does not confirm that those tasks have completed. To confirm completion of the batch through this API, set `cqe = 1` for a task that represents completion of the entire batch. The default `URMA_DEFAULT_CFG` sets `cqe` to `1`, so every task produces a completion record.
- Exclusively own the channel resources associated with the **BatchHandle** while using it. Do not mix ordinary `Drain` calls.

## Call Example

The following shows examples of calling the **Drain** API. To focus on the call flow, the examples omit return value checks and error handling. For complete samples, see [01_hcomm_urma_write_read_nbi](../../../../../examples/aicore/hcomm/01_hcomm_urma_write_read_nbi/README.md) and [02_hcomm_urma_batch_write](../../../../../examples/aicore/hcomm/02_hcomm_urma_batch_write/README.md) (batch).

Common API:

```cpp
// Size of data transferred in a single communication.
constexpr uint64_t BYTES = 1024U;
// Size of the initialized UB temporary workspace: must be no less than 512 bytes.
constexpr uint32_t HCOMM_BUF_SIZE = 512U;

extern "C" __vector__ __global__ __aicore__ void hcomm_drain_kernel(
    uint64_t channel, GM_ADDR localBuffer, GM_ADDR remoteBuffer)
{
    // Prepare the UB temporary workspace; alignas(32) ensures the start address is 32-byte aligned.
    alignas(32) __ubuf__ uint8_t hcommLocal[HCOMM_BUF_SIZE];

    // Create the Hcomm object and initialize the UB temporary workspace.
    AscendC::Hcomm<AscendC::COMM_PROTOCOL_UB_CTP> hcomm;
    hcomm.Init(hcommLocal, HCOMM_BUF_SIZE);

    // Submit the write task.
    hcomm.WriteNbi(channel, remoteBuffer, localBuffer, BYTES);

    // Block until the submitted tasks on the channel are complete.
    hcomm.Drain(channel);
}
```

Batch API:

```cpp
// Size of data transferred in a single communication.
constexpr uint64_t BYTES = 1024U;
// Number of write tasks added in a single batch.
constexpr uint32_t TASK_NUM = 4U;
// Batch workspace size: divided into 64-byte task slots, it must accommodate the slots of the entire batch (the total number of slots must be less than the task submission capacity of the channel).
constexpr uint32_t BATCH_BUF_SIZE = TASK_NUM * 64U;

extern "C" __vector__ __global__ __aicore__ void hcomm_batch_drain_kernel(
    uint64_t channel, GM_ADDR localBuffer, GM_ADDR remoteBuffer)
{
    // Declare the batch UB workspace. The batch API does not depend on Init; alignas(32) ensures the start address is 32-byte aligned.
    alignas(32) __ubuf__ uint8_t hcommLocal[BATCH_BUF_SIZE];

    // Create the Hcomm object.
    AscendC::Hcomm<AscendC::COMM_PROTOCOL_UB_CTP> hcomm;

    // Construct the batch workspace LocalTensor from the start address of the UB workspace.
    AscendC::LocalTensor<uint8_t> batchBuffer(
        AscendC::TPosition::VECOUT,
        static_cast<uint32_t>(reinterpret_cast<uintptr_t>(hcommLocal)), BATCH_BUF_SIZE);

    // Create the batch handle and bind it to the batch workspace.
    auto batchHandle = hcomm.MakeBatchHandle(
        channel, batchBuffer, BATCH_BUF_SIZE, remoteBuffer);

    // Add TASK_NUM write tasks to the current batch in sequence, writing to different remote offsets.
    for (uint32_t i = 0U; i < TASK_NUM; ++i) {
        hcomm.WriteNbi(batchHandle, remoteBuffer + i * BYTES, localBuffer, BYTES);
    }
    hcomm.BatchCommit(batchHandle);

    // Wait for all completion records generated by the entire batch of tasks.
    hcomm.Drain(batchHandle);
}
```
