## Function Description

Header file path: `"hcomm/hcomm_simt.h"`.

Waits for submitted communication tasks to complete. The API provides a common `channel` overload and a batch `batchHandle` overload: the common overload blocks until the tasks submitted on the common channel are complete; the batch overload waits for the completion records generated by the tasks submitted through the batch handle.

## Function Prototype

Common API:

```cpp
template <auto pipe = 0>
__simt_callee__ inline int32_t Drain(ChannelHandle channel);
```

Batch API:

```cpp
template <auto pipe = 0>
__simt_callee__ inline int32_t Drain(UbcCtpBatchHandle& batchHandle);
```

## Parameters

**Table 1** Template parameters

| Parameter | Description |
| --- | --- |
| `pipe` | This parameter is not used on the SIMT path. It is retained only to keep the API signature compatible with the SIMD path, and its default value is **0**. |

**Table 2** API parameters

| Parameter | Input/Output | Description |
| --- | --- | --- |
| `channel` | Input | Communication channel handle used by the common API. |
| `batchHandle` | Input/Output | Batch handle created by [MakeBatchHandle](./SIMT_MakeBatchHandle.md). |

## Return Value

**Table 3** Return values

| Return Value | Description |
| --- | --- |
| `0` | Wait succeeded. |
| `-1` | Wait failed. |

## Usage Constraints

- Currently, only the `COMM_PROTOCOL_UB_CTP` protocol is supported.
- It must be called by a single thread, and only after all threads that submit tasks have returned.

**Common API**

- This overload waits for the completion records generated by the common `channel` call chain.

**Batch API**

- Before calling, all tasks in the current batch must be submitted through [BatchCommit](./SIMT_BatchCommit.md).
- While using the batch handle, the associated channel resources must be exclusively occupied, and the common `Drain` cannot be mixed in.

## Call Example

The following shows an example of calling the **Drain** API. To focus on the call flow, the example omits return value checks and error handling. For complete samples, see [04_simt_hcomm_urma](../../../../../examples/aicore/hcomm/04_simt_hcomm_urma/README.md) and [06_simt_hcomm_urma_batch_perf](../../../../../examples/aicore/hcomm/06_simt_hcomm_urma_batch_perf/README.md).

Common API:

```cpp
__simt_callee__ void SimtDrainOp(AscendC::ChannelHandle channel, __gm__ uint8_t* localBuffer,
    __gm__ uint8_t* remoteBuffer)
{
    AscendC::simt::Hcomm<> hcomm;
    hcomm.Init(nullptr, 0);

    // Submit the write task.
    hcomm.WriteNbi(channel, remoteBuffer, localBuffer, 1024U);

    // Block until the submitted tasks on the common channel are complete.
    hcomm.Drain(channel);
}
```

Batch API:

```cpp
// Size of data transferred in a single communication.
constexpr uint64_t BYTES = 1024U;
// Batch workspace size: no less than 256 bytes, and does not grow with the number of batch tasks.
constexpr uint32_t BATCH_BUF_SIZE = 256U;

__simt_callee__ void SimtBatchDrainOp(
    AscendC::ChannelHandle channel, __gm__ uint8_t* localBuffer, __gm__ uint8_t* remoteBase)
{
    // Declare the batch UB workspace, with the start address aligned to 16 bytes.
    alignas(16) __ubuf__ uint8_t hcommLocal[BATCH_BUF_SIZE];

    AscendC::simt::Hcomm<> hcomm;
    hcomm.Init(nullptr, 0);

    // Create a batch handle and bind it to the batch workspace.
    auto batchHandle = hcomm.MakeBatchHandle(channel, hcommLocal, BATCH_BUF_SIZE);

    // Submit the first batch of tasks.
    hcomm.WriteNbi(batchHandle, remoteBase, localBuffer, BYTES);
    hcomm.BatchCommit(batchHandle);

    // Reuse the batch handle to submit the next batch of tasks.
    hcomm.WriteNbi(batchHandle, remoteBase + BYTES, localBuffer, BYTES);
    hcomm.BatchCommit(batchHandle);

    // Wait for all completion records generated by the accumulated submitted tasks.
    hcomm.Drain(batchHandle);
}
```
