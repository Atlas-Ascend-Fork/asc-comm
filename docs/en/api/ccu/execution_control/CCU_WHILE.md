## Function Description

Header file: `#include "ccu/hcomm/ccu_primitives.hpp"`

`CCU_WHILE` is a preprocessor macro that supports two semantics, which are automatically distinguished by whether a `CCU_DO` precedes it:

1. Standalone while loop: `CCU_WHILE(cond_expr) { body }` - When no `CCU_DO` precedes `CCU_WHILE`, it acts as a normal while loop: the condition is evaluated first in each iteration, and the body is executed only when the condition is met.
2. do-while termination: `CCU_DO { body } CCU_WHILE(cond_expr);` - When a `CCU_DO` precedes `CCU_WHILE`, it acts as the termination of a do-while loop: the condition is evaluated after the body is executed, and if the condition is met, it returns to the beginning of the loop.

The two semantics are completely transparent to users, and the syntax is consistent with the C++ standard while/do-while. For the do-while usage, see [CCU_DO](CCU_DO.md).

## Function Prototype

```cpp
// Semantics 1: standalone while loop.
CCU_WHILE(cond_expr) {
    // body
}

// Semantics 2: do-while termination (must immediately follow CCU_DO { }).
CCU_DO {
    // body
} CCU_WHILE(cond_expr);
```

## Parameters

| Parameter | Description |
| --- | --- |
| cond_expr | Conditional expression of the `AscendC::ccu::cond_expr` type. It is generated by `operator==(uint64_t)` or `operator!=(uint64_t)` of `ccu::variable`, for example, `counter == 10`. The condition is computed by the CCU hardware at the dispatch stage. |

For the definition and generation of `cond_expr`, see [CCU_IF](CCU_IF.md#parameters).

## Return Value

`CCU_WHILE` is a preprocessor macro and does not return [`CcuResult`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_opdev/datatype_definition/CcuResult.md) by itself. If an internal error occurs after macro expansion (such as a duplicate label or an invalid handle), `CCU_E_PARA`/`CCU_E_NOT_FOUND` may be produced. In this case, the macro does not throw an exception and does not block kernel generation: on failure, the body is skipped, but kernel generation still succeeds, and the error is not reported through the return value, so pay attention to it during debugging.

## Usage Constraints

- `CCU_WHILE(cond_expr)` must be immediately followed by a loop code block enclosed in {}.
- `cond_expr` supports only the `==` and `!=` comparison operators. The `<`, `>`, `<=`, and `>=` operators are not supported on any product.
- One side of the comparison in `cond_expr` must be a `uint64_t` immediate value. For Ascend 950PR&950DT products, comparison between `variable` and `variable` is not supported.
- When used as a standalone **while** loop, `CCU_WHILE` can be nested, and an inner `CCU_WHILE` can be used inside the body of an outer `CCU_WHILE`.
- `CCU_WHILE` (standalone while) can be nested in combination with `CCU_IF`.
- `CCU_WHILE` (regardless of its semantics) cannot be used inside the body lambda of `ccu::loop`, because software branches/loops are not supported inside a hardware loop body.

## Call Example

```cpp
using namespace AscendC::ccu;

// Scenario: a standalone while loop that iterates the counter 10 times.
CcuResult my_kernel(ccu_kernel_arg arg) {
    variable counter, one;
    counter = 0;
    one = 1;

    CCU_WHILE(counter != 10ULL) {
        // Loop body.
        counter = counter + one;
    }

    return CCU_SUCCESS;
}
```
