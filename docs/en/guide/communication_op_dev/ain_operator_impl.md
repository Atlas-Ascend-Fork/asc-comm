# Ain-Based Communication Operator Development Guide

<!-- md-trans-meta sourceCommit=5ed547c8af0b4fe59c907ddcd1d49348087706f5 translatedAt=2026-11-05T01:35:12.629Z pushedAt=2026-11-09T06:49:19.124Z nl=2 -->

## Overview

Ain (Ascend-Initiated Networking) is a unilateral communication API template on the AI Core side. It provides unilateral communication capabilities such as `Put`/`Get`/`PutValue`/`Signal` and synchronization capabilities such as `Flush`/`WaitSignal`/`Sync`. Developers do not need to maintain remote physical addresses on the kernel side. Ain automatically resolves the communication channel and communication memory address based on the communication team, peer rank, and symmetric window handle.

This guide uses AllGather as an example to describe the complete development process of an Ain communication operator.

## Supported Scope

| Item | Description |
| --- | --- |
| Communication protocol | `COMM_PROTOCOL_UB_CTP` |
| Communication engine | `COMM_ENGINE_AIV` |

<!-- npu="950" id1 -->
> [!NOTE] Note
> Only the Ascend 950PR&950DT products support implementing Ain operators. In a single-device environment, only compilation verification is supported. Actual running requires at least two NPUs.

## Overall Process

Ain communication operator development consists of two phases: control plane resource preparation and data plane communication execution.

Control plane process:

1. Initialize the operating environment.
2. Create a communicator.
3. Allocate memory resources.
4. Register a symmetric window.
5. Create a communication team.
6. Deliver the team/window handles to the kernel.
7. Destroy communication resources.

Data plane process:

1. Perform preprocessing.
2. Perform pre-synchronization.
3. Initiate a communication task.
4. Perform post-synchronization.

## Control Plane Resource Preparation

### Initializing the Operating Environment

  ```cpp
  uint32_t rank;   // Current rankId
  uint32_t nranks; // Total number of ranks
  aclInit(nullptr);
  aclrtSetDevice(rank);
  aclrtStream stream = nullptr;
  aclrtCreateStream(&stream);
  ```

### Creating a Communicator

All ranks in a communicator must share the same **rootInfo** to create the domain: the root node (rank 0 in this example) calls [`HcclGetRootInfo`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_mgr_c/HcclGetRootInfo.md) to generate **rootInfo**, and distributes the same **rootInfo** to all ranks through inter-rank information exchange. After each rank obtains the **rootInfo**, all ranks jointly call [`HcclCommInitRootInfo`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_mgr_c/HcclCommInitRootInfo.md) to create the communicator.

The sample project exchanges **rootInfo** through a TCP socket control channel centered on rank 0. For details, see [`examples/aicore/utils/rank_sync.h`](../../../../examples/aicore/utils/rank_sync.h) (control channel) and [`examples/aicore/utils/hccl_comm_init.h`](../../../../examples/aicore/utils/hccl_comm_init.h) (**rootInfo** exchange and domain creation).

  ```cpp
  // Control channel endpoint (passed from the command line), in the format "tcp://ip:port".
  std::string endpoint;
  // Establish the TCP control channel: rank 0 listens on the endpoint, and the other ranks connect.
  examples::RankSyncContext sync = (rank == 0) ?
      examples::RankSyncContext::Listen(endpoint, nranks) :
      examples::RankSyncContext::Connect(rank, nranks, endpoint);
  // Generate the rank identifier information of the root node: generated by the root node, and all ranks in the communicator must share the same rootInfo.
  HcclRootInfo rootInfo;
  if (rank == 0) {
      HcclGetRootInfo(&rootInfo);
  }
  // Exchange rootInfo through the control channel AllGather, and all ranks use the rootInfo of rank 0.
  std::vector<HcclRootInfo> allRootInfo(nranks);
  sync.Allgather(examples::kTagRootInfo, &rootInfo, sizeof(rootInfo), allRootInfo.data());
  // Initialize the communicator with the same rootInfo on all ranks.
  HcclComm hcclComm;
  HcclCommInitRootInfo(nranks, &allRootInfo[0], rank, &hcclComm);
  ```

Other methods such as file exchange can also be used: the root node writes **rootInfo** to a file under a shared path, and the other ranks wait for the file to be ready and then read the same **rootInfo**.

### Allocating Memory Resources

Allocate memory: each rank allocates a send buffer, a receive buffer, and a synchronization signal buffer through `HcommMemAlloc`. For details, see [`HcommMemAlloc`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_mgr_c/HcommMemAlloc.md).

In the AllGather scenario, the size of a single shard is one `uint32_t`, and the receive buffer must accommodate `nranks` shards.

  ```cpp
  // Buffer size constants
  constexpr uint64_t SEND_BUF_SIZE = sizeof(uint32_t);   // Size of a single shard
  const uint64_t RECV_BUF_SIZE = SEND_BUF_SIZE * nranks; // Accommodates nranks shards
  constexpr uint64_t SIGNAL_BUF_SIZE = sizeof(uint64_t); // Synchronization signal width

  void* sendBuf = nullptr;
  void* recvBuf = nullptr;
  void* signalBuf = nullptr;
  HcommMemAlloc(&sendBuf, SEND_BUF_SIZE);
  HcommMemAlloc(&recvBuf, RECV_BUF_SIZE);
  HcommMemAlloc(&signalBuf, SIGNAL_BUF_SIZE);
  ```

After allocation, initialize the local data.

  ```cpp
  // Initialize the local input: each shard stores a uint32_t value, which is the local rank ID.
  uint32_t sendVal = rank;
  aclrtMemcpy(sendBuf, SEND_BUF_SIZE, &sendVal, sizeof(sendVal), ACL_MEMCPY_HOST_TO_DEVICE);

  // Self-fill the local shard: copy sendBuf to the rankId shard of the local recvBuf.
  aclrtMemcpy(static_cast<uint8_t*>(recvBuf) + static_cast<uint64_t>(rank) * SEND_BUF_SIZE, SEND_BUF_SIZE,
      sendBuf, SEND_BUF_SIZE, ACL_MEMCPY_DEVICE_TO_DEVICE);
  ```

### Registering Symmetric Windows

Register the local send buffer, receive buffer, and synchronization signal buffer as symmetric windows respectively. Each rank must register the corresponding window with the same memory address and size to implement symmetric access. For details, see [`HcclCommSymWinRegister`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_mgr_c/HcclCommSymWinRegister.md).

  ```cpp
  HcclCommSymWindow sendWin{nullptr};
  HcclCommSymWinRegister(hcclComm, sendBuf, SEND_BUF_SIZE, &sendWin, 1);

  HcclCommSymWindow recvWin{nullptr};
  HcclCommSymWinRegister(hcclComm, recvBuf, RECV_BUF_SIZE, &recvWin, 1);

  HcclCommSymWindow signalWin{nullptr};
  HcclCommSymWinRegister(hcclComm, signalBuf, SIGNAL_BUF_SIZE, &signalWin, 1);
  ```

### Creating a Communication Team

Configure the team description and create the team. For details, see [`HcclTeamCreateDescInit`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_opdev/control_plane_api/comms_domain_resource_mgmt/HcclTeamCreateDescInit.md) and [`HcclTeamCreate`](https://gitcode.com/cann/hcomm/blob/master/docs/en/api_ref/comm_opdev/control_plane_api/comms_domain_resource_mgmt/HcclTeamCreate.md).

  ```cpp
  HcclTeamCreateDesc desc;
  HcclTeamCreateDescInit(&desc);
  std::vector<uint32_t> worldRankIds;
  for (uint32_t idx = 0; idx < nranks; idx++) {
      worldRankIds.emplace_back(idx);
  }
  desc.rankIds = worldRankIds.data();
  desc.rankNum = nranks;
  desc.selfRankId = rank;
  desc.netLayer = 0;
  desc.requirement.barrierCount = 1;
  desc.engine = COMM_ENGINE_AIV;
  desc.protocol = COMM_PROTOCOL_UB_CTP;
  desc.channelCnt = 1;
  HcommTeamHandle team{nullptr};
  HcclTeamCreate(hcclComm, &desc, &team);
  ```

### Delivering Handles to the Kernel

Deliver the device-side handles such as `team`, `sendWin`, `recvWin`, and `signalWin` to the kernel as input parameters.

  ```cpp
  all_gather_kernel<<<1U, nullptr, stream>>>(team, sendWin, recvWin, signalWin, nranks, rank);
  aclrtSynchronizeStream(stream);
  ```

### Destroying Communication Resources

After the communication task is complete, destroy the communication resources. The destruction order is the reverse of the creation order.

  ```cpp
  // Destroy the team.
  HcclTeamDestroy(team);
  // Unregister the windows.
  HcclCommSymWinDeregister(signalWin);
  HcclCommSymWinDeregister(recvWin);
  HcclCommSymWinDeregister(sendWin);
  // Release the allocated memory.
  HcommMemFree(sendBuf);
  HcommMemFree(recvBuf);
  HcommMemFree(signalBuf);
  // Destroy the communicator.
  HcclCommDestroy(hcclComm);
  // Deinitialize.
  aclrtDestroyStream(stream);
  aclrtResetDevice(static_cast<uint32_t>(rank));
  aclFinalize();
  ```

## Kernel-Side Communication Execution

The kernel entry function is as follows. The team and symmetric window handles are passed in as pointers, and the subsequent steps are carried out within this function.

  ```cpp
  extern "C" __global__ __aicore__ void all_gather_kernel(
      __gm__ void* team, __gm__ void* sendWin, __gm__ void* recvWin, __gm__ void* signalWin,
      uint32_t rankNum, uint32_t rankId)
  {
      // The subsequent kernel-side communication execution tasks are carried out within this function
  }
  ```

### Performing Preprocessing

The following preparations are required before a communication task is delivered.

  ```cpp
  // Prepare the UBuf workspace: the Put/Get/PutValue/Signal APIs require a UBuf temporary workspace of no less than 512B.
  // alignas(32) ensures that the start address is 32-byte aligned.
  alignas(32) __ubuf__ uint8_t hcommLocal[AscendC::HCOMM_URMA_TMP_BUF_SIZE];
  AscendC::AinDescriptorUbuf hcommUbuf{hcommLocal, AscendC::HCOMM_URMA_TMP_BUF_SIZE, 0U};
  // Create the Ain and AinBarrierSession objects.
  AscendC::Ain ain(0);
  AscendC::AinBarrierSession ainBarrier(&ain, team, 0);
  // Read the initial value of the synchronization signal.
  uint64_t signalVal = ain.ReadSignal(team, signalWin, 0);
  ```

### Performing Pre-Synchronization

Pre-Synchronization: ensures that all ranks complete preprocessing, that the initial signal value read is not contaminated by remote communication, and that subsequent communication is executed only after preprocessing is ready.

  ```cpp
  ainBarrier.Sync(AscendC::AinMemoryOrder::AIN_MEMORY_ORDER_RELAX, hcommUbuf);
  ```

### Initiating a Communication Task

AllGather: submits a `Put` communication task to other ranks and sends a `Signal` synchronization signal to the peer.

  ```cpp
  for (uint32_t peer = 0; peer < rankNum; peer++) {
      if (peer == rankId) {
          continue;
      }
      ain.Put(
          team, peer, recvWin, rankId * SEND_BUF_SIZE, sendWin, 0U, SEND_BUF_SIZE,
          AscendC::AinSignalInc{signalWin, 0}, hcommUbuf);
  }
  ```

### Performing Post-Synchronization

Block until all ranks have received data from other ranks and AllGather is complete.

  ```cpp
  // Local synchronization: wait for the Put communication task to complete.
  ain.Flush(team);
  // Remote point-to-point synchronization: block until data from all other ranks is received.
  ain.WaitSignal(team, signalWin, 0, signalVal + rankNum - 1);
  // Barrier synchronization: block until all ranks have received data from other ranks.
  ainBarrier.Sync(AscendC::AinMemoryOrder::AIN_MEMORY_ORDER_RELAX, hcommUbuf);
  ```

## Delayed Commit and Batch Optimization

The default commit mode is `AIN_COMMIT_IMMED`, which commits immediately on each call. When multiple communication tasks need to be committed, you can use `AIN_COMMIT_DELAYED` to delay the commit, and set `AIN_COMMIT_IMMED` only on the last task to implement batch commit, thereby reducing overhead.

  ```cpp
  // Config for delayed commit
  static constexpr struct AscendC::UrmaWqeEntry COMMIT_DELAYED_CONFIG = {
    .odr = 5,   // Relax order
    .fence = 1, // Enable fence. The operation can be executed only after the preceding read or atomic operations are complete.
    .se = 0,    // Do not generate a request event.
    .cqe = 0,   // Do not generate a CQE in the delayed commit scenario.
    .inlineEn = 0,
  };
  // Config for the last commit
  static constexpr struct AscendC::UrmaWqeEntry COMMIT_IMMED_CONFIG = {
    .odr = 6,   // Strong order
    .fence = 1, // Enable fence. The operation can be executed only after the preceding read or atomic operations are complete.
    .se = 0,    // No request event is generated.
    .cqe = 1,   // A CQE is generated in the last commit.
    .inlineEn = 0,
  };
  // Delayed commit: only assemble the WQE without committing.
  ain.Put<AscendC::AinRemoteNone, AscendC::AinDescriptorUbuf, AscendC::AIN_COMMIT_DELAYED, COMMIT_DELAYED_CONFIG>(
      team, peer, recvWin, dstOffset,
      sendWin, 0U, dataLen, AscendC::AinRemoteNone{}, hcommUbuf);
  // ... More delayed commit tasks
  // Use AIN_COMMIT_IMMED for the last commit to trigger submission in a unified manner.
  ain.Put<AscendC::AinRemoteNone, AscendC::AinDescriptorUbuf, AscendC::AIN_COMMIT_IMMED, COMMIT_IMMED_CONFIG>(
      team, peer, recvWin, dstOffset2,
      sendWin, 0U, dataLen2, AscendC::AinRemoteNone{}, hcommUbuf);
  ain.Flush(team);
  ```

Constraints:

- When `AIN_COMMIT_DELAYED` is used, the number of consecutive calls must not exceed the SQ (Send Queue) depth (`sqDepth`).
- In batch commit scenarios, only the last `AIN_COMMIT_IMMED` should generate a CQE (Completion Queue Element).

## Asynchronous Wait

`Flush` blocks and waits for the communication channel tasks of all peers in the team to complete. If you only need to wait for the communication channel task of a specific peer, use `FlushAsync`+`Wait` to implement asynchronous waiting, avoiding blocking the current kernel execution.

  ```cpp
  // Obtain the channel handle of the specified peer.
  AscendC::ChannelHandle handle;
  ain.FlushAsync(team, peer, &handle);
  // ... Perform other computations.
  // Wait for the communication channel task of this peer to complete.
  ain.Wait(handle);
  ```

## Precautions

- The single data length range of `Put`/`Get` is `0 < bytes <= 256MB`.
- `Ain` currently supports only the `COMM_PROTOCOL_UB_CTP` protocol path.
- `AinDescriptorUbuf` requires a UBuf (Unified Buffer) temporary workspace of no less than 512 B.
- A symmetric window must be registered with the same memory address and size on all ranks. `Put`/`Get`/`PutValue`/`Signal` locate data by offset.
- The `Signal` address shall be prepared according to `uint64_t` alignment access requirements.
