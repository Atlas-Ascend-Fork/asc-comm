# 资料贡献指南

本文档说明asc-comm资料文档的补充和修改要求。资料修改应优先保证准确、可验证、边界清晰。

## 适用范围

适用于`README.md`、`docs/`、`examples/`、`CONTRIBUTING.md`以及Issue/PR模板中的说明性内容。

## 基本原则

- 与代码一致：目录结构、构建命令、接口名称和返回值应与当前仓库实际内容一致。
- 边界清晰：当前仓只迁移部分通信相关能力时，需要明确哪些能力已迁移、哪些依赖外部仓库。
- 面向验证：快速开始、构建测试和样例文档应说明用户能直接执行什么、不能直接执行什么。
- 链接有效：新增文档后需要同步更新入口页面，避免孤立文档。

## 推荐结构

新增专题文档建议包含以下内容：

- 背景或适用范围。
- 前置条件和依赖。
- 操作步骤或接口使用流程。
- 当前限制和外部依赖边界。
- 相关文档链接。

## 常见修改场景

- 新增接口：同步更新API参考、使用指南、样例说明和文档入口。
- 新增样例：同步更新`examples/README.md`，说明样例是否可独立运行。
- 修改构建流程：同步更新快速开始、构建与测试文档。
- 新增依赖：同步更新三方依赖说明、三方软件清单和Notice。

## 提交前检查

- 使用UTF-8编码保存Markdown文档。
- 确认Markdown表格、代码块和相对链接格式正确。
- 确认文档没有描述尚未迁移或尚不可用的能力，除非明确标注为外部依赖或后续规划。
- 文档中引用外部仓库能力时，优先说明当前asc-comm仓的边界。
