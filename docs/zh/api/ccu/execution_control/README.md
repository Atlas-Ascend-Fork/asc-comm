# 简介

提供CCU kernel内的流程控制接口，用于条件分支、并发循环与函数块等任务编排。三种子类按适用场景选择：

| 子类 | 适用场景 | 接口 |
| --- | --- | --- |
| 软件分支 | 控制流逻辑复杂、有嵌套，循环体内可用任意CCU接口 | [CCU_IF](CCU_IF.md) |
| 硬件Loop | 大量同结构迭代，循环体内只有本地搬运类操作，追求最小指令开销 | [loop](loop.md)、[loop_group](loop_group.md) |
| 函数块 | 同一段逻辑在kernel内被调用两次或以上，只生成一份指令，节省指令空间 | [func](func.md)、[call_func](call_func.md) |

## 两阶段中的工作机制

流程控制接口在注册阶段完成定义与合成，执行阶段由CCU硬件驱动。三种子类解决不同的编排需求：软件分支以灵活的条件跳转组织执行路径，硬件Loop以硬件迭代实现循环并追求最小指令开销，函数块让同一段逻辑只生成一份指令、多处调用复用。三者也常组合使用——在分支内编排Loop、把Loop的循环体或函数块的逻辑交给`func`承载。

各子类内接口在两个阶段中的行为如下。

**软件分支**：`CCU_IF`是宏，注册阶段随Kernel函数体展开，then代码块内的接口调用被记录为指令；执行阶段由硬件计算条件，满足则执行then代码块，不满足则跳转到块出口。

**硬件Loop**：接口分定义与合成两步。

1. 构造[loop](loop.md)：执行`func`承载的循环体lambda，把逻辑记录为一份循环体指令。
2. 构造[loop_group](loop_group.md)：把各`loop`的迭代参数（循环次数、地址偏移）与复制参数写入，合成硬件循环指令；`loop`必须加入`loop_group`，否则不产生循环效果。

执行阶段，LoopEngine执行到循环指令时按设定的参数迭代执行循环体，每轮按偏移更新数据地址；`loop_group`复制的多份循环体并行执行。

**函数块**：接口分定义与调用两步。

1. 构造[func](func.md)：仅记录lambda，不生成指令。`func`有两种用途——作为循环体交给`loop`，或作为函数块由[call_func](call_func.md)调用。
2. 调用[call_func](call_func.md)：首次调用执行lambda，合成为一份函数块指令并追加一条跳转指令；后续调用只追加跳转指令。

执行阶段，硬件执行到跳转指令时进入函数块，一份指令在多处复用。

> [!NOTE]说明
> - 允许在软件分支内嵌套硬件Loop；
> - 硬件Loop的循环体内不可使用软件分支，代码不会报错，但硬件会发生未定义行为。
