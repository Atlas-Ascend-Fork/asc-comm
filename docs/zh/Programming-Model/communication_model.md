# 代理模式

本文介绍 Ascend 950 上的代理模式通信模型。在代理模式下，通信的发起方与执行方分离：AI Core 作为通信客户端发起通信请求，AICPU_TS 或 CCU 作为通信服务端执行通信任务。AICPU_TS 或 CCU 直接发起并执行通信的形态参见[直驱模式通信模型](./direct_comm_model.md)。

## 模型概述

代理模式用于通算融合场景。AI Core 作为通信客户端，可以驱动 AICPU_TS 或 CCU 通信服务端执行通信任务。AI Core 负责准备并下发通信任务，通信服务端负责展开和执行任务，再将完成状态反馈给 AI Core。

两种代理模式分别使用对应的任务传递和完成反馈机制，并复用 Channel 两端的通信关系和远端内存访问模型。通信内存的注册、远端地址和访问授权参见[内存模型](./memory_model.md)。

## AICPU_TS 服务端

使用 AICPU_TS 服务端时，AI Core 与 AICPU_TS 之间通过消息区代理通信任务。消息区保存任务参数和执行状态，Channel 对应的通信通路传输跨 rank 用户数据。

**图1** AICPU_TS 代理模式通信模型

![](./figures/aicpu_proxy_communication_model.png "AICPU_TS代理模式通信模型")

通信任务按以下流程执行：

1. AI Core 客户端将通信原语类型、收发地址、数据量和数据类型等任务参数写入消息区，并获得用于标识该任务的任务标识。
2. AI Core 客户端在需要执行该任务时通知 AICPU_TS 服务端。
3. AICPU_TS 服务端从消息区读取任务参数，根据任务使用的 Channel 展开并执行通信操作。
4. AICPU_TS 服务端将执行进度或完成状态写回消息区，AI Core 客户端通过任务标识查询或等待对应任务完成。

## CCU 服务端

使用 CCU 服务端时，AI Core 与 CCU 之间通过 CCU 通用寄存器和同步寄存器代理通信任务。通用寄存器用于传递任务参数，同步寄存器分别用于传递任务启动和完成事件，相关代理介质由库提供和管理。

**图2** CCU 代理模式通信模型

![](./figures/ccu_proxy_communication_model.png "CCU代理模式通信模型")

通信任务按以下流程执行：

1. 每个未完成任务占用一个 CCU 任务槽位。任务槽位包含一组用于承载任务参数的通用寄存器，以及用于启动和完成通知的同步寄存器。AI Core 客户端调用通信原语准备任务并获得任务标识。
2. AI Core 客户端调用 `Commit` 后，选择可用任务槽位，将通信原语类型、收发地址和数据量等任务参数写入该槽位对应的通用寄存器，并置起启动同步寄存器，通知 CCU 服务端执行任务。
3. CCU 指令流等待启动同步寄存器置位后，读取对应通用寄存器中的任务参数，根据任务使用的 Channel 展开并执行通信操作。
4. 通信任务完成后，CCU 服务端置起该任务槽位对应的完成同步寄存器。AI Core 客户端调用 `Wait` 等待对应任务完成；完成事件被消费后，该任务槽位才可用于新任务。

CCU 服务端可同时保留的未完成任务数量受 CCU 通用寄存器和同步寄存器构成的任务槽位数量限制。当所有任务槽位均被占用时，新任务需要等待已有任务完成并释放槽位后才能下发。

## 服务端差异

| 对比项 | AICPU_TS 服务端 | CCU 服务端 |
| --- | --- | --- |
| 客户端 | AI Core | AI Core |
| 任务传递介质 | 消息区 | CCU 通用寄存器和同步寄存器 |
| 任务启动 | AI Core 通知 AICPU_TS 处理消息区中的任务 | AI Core 置起任务槽位对应的启动同步寄存器 |
| 完成反馈 | AICPU_TS 将执行状态写回消息区 | CCU 置起任务槽位对应的完成同步寄存器，AI Core 通过 `Wait` 等待完成 |
| 服务端通信资源 | Endpoint、Channel、Notify、通信内存 | Endpoint、Channel、Notify、Variable、通信内存、CcuBuffer |
