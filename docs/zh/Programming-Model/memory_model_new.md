# 内存模型

通信会涉及多种内存资源。下表汇总了通信编程中常见内存的物理位置及其跨端访问能力。

| 内存资源 | 物理位置 | 本端参与跨端访问 | 对端发起访问 |
| --- | --- | --- | --- |
| Global Memory（GM） | Device 全局内存 | 远端写时可作为本端源，远端读时可作为本端目的 | 通信内存向对端开放后，可作为远端读的源或远端写的目的 |
| L2 Cache | Device 核外共享缓存 | 缓存本端 GM 数据，不作为独立的通信操作数 | 不支持作为独立的通信操作数 |
| Unified Buffer（UB） | AI Core 片内 | 不作为远端读写的本端操作数 | 不支持作为远端读写的操作数 |
| AI Core 寄存器 | AI Core 片内 | 不作为远端读写的本端操作数 | 不支持作为远端读写的操作数 |
| Memory Slice | CCU 片内 | 远端写时可作为本端源，远端读时可作为本端目的 | 不支持作为远端读写的操作数 |
| CCU 寄存器 | CCU 片内 | 可通过 Channel 向对端写入地址、`Token`、数据长度等通信参数，或发送同步通知 | 可通过 Channel 接收对端写入的通信参数或同步通知 |

- GM 按主要用途可以分为计算内存和通信内存。计算内存保存计算的输入、输出和中间结果；通信内存承载跨端传输的源数据和目的数据。
- L2 Cache 位于 GM 与执行单元的访存路径之间。远端写请求通过访问校验后，写入目标 GM 地址对应的 L2 Cache；L2 Cache 与 GM 之间的数据一致性由硬件维护。
- UB 位于 AI Core 内部。在通算融合过程中，计算数据通过 UB 在计算单元与 GM 之间搬运；计算结果需要参与通信时，先从 UB 搬到 GM 中的通信内存，通信数据到达本端 GM 后也可以搬入 UB 继续计算。
- Memory Slice 是 CCU 内部的片上存储资源，用于暂存、中转和归约通信数据。
- CCU 寄存器位于 CCU 内部，用于保存访问地址、`Token`、数据长度等通信参数和同步状态。

## 通信内存

通信内存在物理上位于 GM，是经过控制面准备、能够作为通信操作数并可向对端开放的内存范围。通信内存承载跨端传输的源数据和目的数据。

通信开始前，控制面记录通信内存的有效范围，并为其建立通信关系和访问授权；数据面依据这些资源执行通信操作。通信内存从准备到组织的过程如下图所示。

![通信内存的准备与组织](./figures/communication_memory_flow.png)

下文依次说明通信内存如何建立远端可见性、访问凭据如何保护内存范围，以及程序如何组织通信内存并描述目标成员和内存位置。


### 远端可见性

一段 GM 内存通过以下步骤建立远端可见性：

1. 控制面记录内存的起始地址、大小和有效范围。
2. 控制面按照通信协议注册该内存，并为有效范围建立访问凭据。
3. 建立 Channel，确定该 Channel 可以使用的通信内存。
4. 向对端交换内存描述和远端访问所需的凭据。

完成上述准备后，对端获得目标内存的地址范围和访问授权，并可以通过已建立的 Channel 访问该段内存。

具备远端可见性后，通过以下信息发起远端访问：

- Channel 用于确定通信对端和已经建立的通信关系。
- 远端地址和访问长度用于描述对端内存中的目标范围。
- 访问凭据用于表明本次操作获得了目标内存范围的访问授权。

Channel、远端地址和访问长度、访问凭据共同指向同一对端注册内存范围。远端地址作为通信任务的远端操作数，通过通信操作交给通信硬件，用于表示对端地址空间中的位置。通信硬件完成匹配和校验后执行访问。


### 访问凭据

访问凭据由内存注册过程为注册范围建立，用于表达通信任务对该范围的访问授权。建立 Channel 时，目标内存的地址范围及远端访问所需的凭据会交换给对端；执行通信任务时，通信硬件依据凭据校验对本地或远端注册内存的访问。不同通信协议采用的凭据机制如下。

| 协议类型 | 访问凭据 | 校验机制 |
| --- | --- | --- |
| RoCE | `lkey`、`rkey` | `lkey` 用于校验通信引擎对本地操作数的访问，`rkey` 用于校验对目标端注册内存的远端访问 |
| UB 类协议 | `tokenId`、`tokenValue` | `tokenId` 用于定位目标内存对应的保护信息，`tokenValue` 用于校验访问权限；二者需要与目标地址范围匹配 |

#### RoCE 访问过程

以成员 0 将本端内存 A 写入成员 1 的内存 B 为例：

1. 成员 0 注册内存 A，获得用于本地访问的 `lkey_A`。
2. 成员 1 注册内存 B，获得用于授权远端访问的 `rkey_B`。
3. 建立 Channel 时，成员 1 将内存 B 的地址范围和 `rkey_B` 交换给成员 0。
4. 成员 0 发起写操作时，通信任务携带内存 A 的本地地址和 `lkey_A`，以及内存 B 的远端地址和 `rkey_B`。
5. 发起端通信硬件使用 `lkey_A` 校验对内存 A 的读取，目标端通信硬件使用 `rkey_B` 校验对内存 B 的写入。两项校验通过后，数据才能写入内存 B。

![RoCE 远端写访问过程](./figures/roce_remote_write.png)

一次 RoCE 远端写同时使用发起端本地源内存的 `lkey` 和目标端目的内存的 `rkey`。二者分别保护本地操作数和远端操作数，并与各自的注册内存范围匹配。

#### UB 类协议访问过程

仍以成员 0 将本端内存 A 写入成员 1 的内存 B 为例：

1. 成员 1 注册内存 B，为该内存范围建立 `tokenId_B` 和 `tokenValue_B`。
2. 建立 Channel 时，成员 1 将内存 B 的地址范围、`tokenId_B` 和 `tokenValue_B` 交换给成员 0。
3. 成员 0 发起写操作时，通信任务携带内存 B 的远端地址、访问长度、`tokenId_B` 和 `tokenValue_B`。
4. 目标端通信硬件根据 `tokenId_B` 定位内存 B 对应的保护信息，使用 `tokenValue_B` 校验访问权限，并检查远端地址和访问长度是否落在该保护信息对应的注册范围内。
5. `Token` 和目标内存范围均匹配后，数据才能写入内存 B。

![UB 类协议远端写访问过程](./figures/ub_remote_write.png)

完成内存注册、Channel 建立和访问凭据交换后，通信双方已经具备访问对端通信内存的基础条件。上层编程模型还需要向用户提供一种方式，用于指定目标成员及其内存位置。

### 通信内存的组织

根据通信内存向用户呈现的组织方式，可以分为非对称内存和对称内存。两种组织方式都建立在 Channel、实际 GM 地址范围和访问凭据之上，区别在于用户如何指定目标成员和内存位置。

两种组织方式的差异如下表所示。

| 组织方式 | 用户看到的内存组织 | 每次操作提供的信息 | 底层处理方式 |
| --- | --- | --- | --- |
| 非对称内存 | 各成员分别管理通信内存 | Channel、本地地址和远端地址 | 根据 Channel 确定目标成员，根据地址范围匹配注册内存和访问凭据 |
| 对称内存 | 各成员的对应内存组成逻辑窗口 | 目标成员、窗口和窗口内偏移 | 选择目标成员对应的 Channel，将偏移解析为实际地址并匹配访问凭据 |

#### 非对称内存

非对称内存是指各成员的通信内存彼此独立，不同成员的内存大小、布局和实际地址可以不同，不要求形成统一的逻辑布局。采用非对称内存时，各通信成员分别申请和管理自己的通信内存。

发起通信时，用户通过 Channel 指定目标成员，并分别提供本地地址和远端地址。底层根据 Channel 确定通信对端，根据地址和长度匹配已注册的内存范围及其访问凭据。

```text
Channel + 本地地址 + 远端地址 + 访问长度
        -> 确定目标成员
        -> 匹配本地和远端注册内存范围
        -> 匹配访问凭据并传输数据
```

HComm 和 CCU 是采用这类内存组织的示例；具体通信对象和地址参数可参考接口章节说明。

##### HComm 示例

以下示例场景用于进一步说明非对称内存。

假设成员 0 要把本端通信内存 A 中偏移 64 字节开始的 256 字节数据，写入成员 1 的通信内存 B 中偏移 128 字节的位置。A 和 B 由两个成员分别准备，其起始地址和内存布局不需要相同。建立 Channel 时，成员 1 的内存 B 及其远端访问凭据已经交换给成员 0。HComm 伪码实现：

```cpp
// localMemA：本端通信内存 A 的起始地址
// remoteMemB：成员 1 的通信内存 B 的远端起始地址
auto localAddr = localMemA + 64;
auto remoteAddr = remoteMemB + 128;

hcomm.WriteNbi(
    channelToMember1, // 通往成员 1 的 Channel
    remoteAddr,       // 远端目的位置
    localAddr,        // 本地源位置
    256);             // 传输长度，单位为字节
```

调用中的 `channelToMember1`、`localAddr` 和 `remoteAddr` 分别确定目标成员、本地源位置和远端目的位置。HComm 随后完成以下处理：

1. 根据 Channel 确定目标成员 1。
2. 确认本地和远端访问范围分别落在已注册的内存 A 和内存 B 中。
3. 根据实际通信协议匹配本次访问所需的 `lkey`、`rkey` 或 `Token`，并发起数据传输。

用户在每次操作中显式提供 Channel、本地地址和远端地址，HComm 根据这些地址所在的注册内存范围，在 Channel 内部匹配相应的访问凭据。

#### 对称内存
以下示例场景用于进一步说明对称内存。

采用对称内存时，各通信成员分别提供一段本端通信内存，这些对应内存被共同组织为一个逻辑窗口。用户通过目标成员、窗口和窗口内偏移描述访问位置，底层据此解析 Channel 和远端实际地址。

```text
目标成员 + 逻辑窗口 + 窗口内偏移 + 访问长度
        -> 选择该成员对应的 Channel 和窗口内存
        -> 将窗口内偏移解析为实际 GM 地址
        -> 匹配访问凭据并传输数据
```

对称性体现在各成员使用一致的逻辑组织和偏移规则，各成员对应内存的实际地址可以不同。窗口中的每个成员对应一段实际 GM，底层选择目标成员对应的 Channel，将偏移换算为实际地址，并使用与该内存范围匹配的访问凭据。

AIN 是采用这类编程形态的示例，编程算子实现由相应接口和算子实现章节说明。

##### AIN 示例

假设一个逻辑窗口由成员 0、成员 1 和成员 2 各自提供的一段通信内存组成，这三段内存的实际起始地址可以不同。成员 0 要把本地窗口中偏移 64 字节开始的 256 字节数据写入成员 2 的窗口偏移 128 字节处。AIN 伪码实现：

```cpp
ain.Put(
    communicationGroup, // 当前通信组
    2,                  // 目标成员
    window, 128,        // 目的窗口及窗口内偏移
    window, 64,         // 源窗口及窗口内偏移
    256,                // 传输长度，单位为字节
    /* 其余参数省略 */);
```

与 HComm 示例相比，这次调用没有直接给出通往成员 2 的 Channel 和远端 GM 地址，而是通过目标成员、窗口和窗口内偏移表达访问位置。AIN 随后完成以下处理：

1. 根据目标成员 2 选择通往该成员的 Channel。
2. 使用窗口中记录的成员 0 实际内存起始地址加源偏移，得到本地 GM 地址。
3. 使用窗口中记录的成员 2 实际内存起始地址加目的偏移，得到远端 GM 地址。
4. 通过底层 HComm 匹配相应的访问凭据并发起写操作。

用户面对的是统一的逻辑窗口、目标成员和窗口内偏移。底层 Channel、实际 GM 地址和访问凭据由 AIN 及其复用的 HComm 完成解析和匹配。

## CCU 片上内存模型

通信内存位于 GM，用于承载跨端传输的源数据和目的数据，并通过内存注册、Channel 和访问凭据建立远端访问条件。CCU 执行通信任务时，使用片上的 Memory Slice 暂存、中转和归约数据，并使用寄存器保存搬运参数和同步状态。这两类片上资源共同配合 GM 中的通信内存完成数据搬运和处理。

### Memory Slice

Memory Slice 是 CCU 内部的片上缓存分片，每个分片大小为 4 KB。

Memory Slice 支持以下数据搬运路径：

- 本地搬运：本端 GM 与本端 Memory Slice 之间可以双向搬运数据。
- 读取远端：本端 CCU 从对端 GM 读取通信数据，并写入本端 Memory Slice 。
- 写入远端：本端 CCU 从本端 Memory Slice  读取数据，并写入对端 GM。

跨端搬运由持有 Memory Slice  的本端 CCU 发起，远端操作数位于对端 GM。对端发起远端写时，目的范围位于本端 GM 中的通信内存。

归约时，CCU 可以将不同来源的数据暂存在多个 Memory Slice  中，在片上按序完成归约，再将结果写入本端或对端 GM。中间数据保留在 CCU 片上，可以减少集合通信过程中对 GM 的重复读写。Memory Slice  的分配、数据搬运和归约操作由 CCU 编程接口及算子实现章节说明。

### CCU 寄存器

CCU 寄存器位于 CCU 硬件内部，包括地址寄存器、通用寄存器和同步寄存器。三类寄存器分别承担以下作用：

- 地址寄存器保存 CCU 数据搬运所需的 GM 地址，并支持根据地址偏移更新数据位置。
- 通用寄存器保存通信任务使用的数据，例如通信内存地址、`Token`、数据长度等。CCU 可以从本端 GM 将这些数值加载到通用寄存器，也可以将通用寄存器中的数值写回本端 GM。
- 同步寄存器包含多个事件位，每个事件位表示一个需要等待的条件，例如数据搬运完成、前序任务完成或对端通知到达。条件满足后，对应的事件位被置位，CCU 随后继续执行。

在需要通过寄存器交换远端 GM 地址和 `Token` 的 CCU 算子编排中，读写双方按以下过程传递参数并进行同步：

- 被访问 GM 所在的一方通过 Channel，将通信内存的地址和 `Token` 分别写入读写发起方的通用寄存器，并置位双方约定的通知事件。
- 读写发起方等待通知事件，读取地址和 `Token`，将地址装入地址寄存器，并使用地址和 `Token` 访问对端 GM。
- 数据搬运完成后，读写发起方可以置位对端的通知事件，告知对端数据已经就绪或本轮搬运已经完成。

CCU 任务通过寄存器传递通信参数和同步状态，通信的用户数据通过 GM 或 Memory Slice  相关的数据路径传输。具体的寄存器分配、数据加载和同步操作由 CCU 编程接口及算子实现章节说明。
