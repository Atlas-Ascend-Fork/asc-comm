# 内存模型文档评审与整改清单

## 评审范围

本文记录对 [memory_model_new.md](./memory_model_new.md) 的结构和表达评审结果，用于后续逐项修改和验收。

本次评审重点检查以下内容：

- 概念是否在首次出现时得到清晰说明。
- 是否使用正面机制说明能力，而不是在机制不清楚时只说明限制。
- 章节之间是否形成由整体到局部、由底层条件到上层组织的递进关系。
- 表格、流程和图片是否能够直观呈现上述递进关系。

## 整体结论

当前文档的总体方向正确，已经形成以下基本主线：

```text
内存资源总览
    -> GM 中的通信内存
    -> 本地与远端可见性
    -> 访问凭据
    -> 非对称内存与对称内存
    -> L2 Cache 和执行引擎片内资源
```

仍需解决的问题主要包括：部分章节为空、标题与内容不一致、表格维度不统一、通信内存的概念主线缺少完整图示、部分实现细节前置，以及若干使用否定句代替正面机制说明的表达。

#### [x] 8. 清理可以直接正面表述的否定句

处理结果：已正面说明通信内存的物理位置，以及非对称内存和对称内存的组织机制；能力表、远端地址和 `CcuBuffer` 相关段落继续保留必要的访问边界。

重点位置和建议方向：

| 当前表达方向 | 建议表达方向 |
| --- | --- |
| 通信内存不是独立的物理层级 | 通信内存在物理上位于 GM，是具备通信属性的一段 GM 范围 |
| 两种组织方式不会改变底层要求 | 两种组织方式共同建立在 Channel、GM 地址范围和访问凭据之上 |
| 非对称内存不要求统一逻辑布局 | 非对称内存由各成员独立确定大小、布局和实际地址 |
| 对称性不表示实际地址相同 | 对称窗口采用一致的逻辑组织，各成员实际地址可以不同 |

说明：

- 能力表中的“不支持直接访问”可以保留，因为它直接给出能力边界。
- `CcuBuffer` 章节先列出支持路径，再说明不能被对端直接写入，这种“能力加边界”的结构可以保留。

完成标准：

- 概念定义以“是什么、如何工作”为主。
- 否定句主要用于补充必要的能力边界，不承担首次解释机制的职责。

## 建议整改顺序

建议按以下顺序执行，以减少反复修改：

1. 完成第 1、2 项，补齐章节并确定可见性定义。
2. 完成第 3、4、5、6 项，固定全文结构和视觉主线。
3. 完成第 7、8 项，统一正面机制说明方式。
4. 完成第 9、10 项，调整实现细节的层级。
5. 完成第 11、12 项，精简示例并统一术语。

每完成一项，应同时检查开头资源表、内存层级图、对应正文和示例是否保持一致。
