# 代理模式

在代理模式下，当前算子 Kernel 通过 AI Core 通信客户端提交请求，通信服务端根据请求完成本端与对端之间的数据传输，并将完成状态返回给 AI Core。服务端类型以及通信请求的传递方式参见[通信模型](./communication_model.md)。

Host 侧在 Kernel 启动前准备通信资源和通信上下文，并启动 AI Core 计算任务和通信服务端。Kernel 执行期间，AI Core 客户端负责描述通信任务、确定任务何时可以执行以及等待任务完成；通信服务端负责取得任务参数、展开通信算法、通过 Channel 执行通信操作并反馈完成状态。

代理执行模型包含以下两类服务端：

- AICPU_TS 服务端：AI Core 与 AICPU_TS 通过消息区传递任务参数、任务发布状态和完成状态。
- CCU 服务端：AI Core 与 CCU 通过 CCU 通用寄存器传递任务参数，通过同步寄存器传递任务启动和完成状态。


## 代理执行机制

**图1** 代理模式执行机制

![](./figures/proxy_execution_model.png "代理模式执行机制")

代理模式包含以下参与方：

| 参与方 | 职责 |
| --- | --- |
| Host | 申请通信资源，准备通信上下文和通信算法 Tiling，启动通信服务端和 AI Core Kernel |
| AI Core 客户端 | 准备通信任务，发布任务执行条件，等待完成状态，并在任务完成后消费结果或复用资源 |
| 代理介质 | 在客户端与服务端之间传递任务参数、任务启动状态和完成状态 |
| AICPU_TS 或 CCU 服务端 | 取得并解析任务参数，展开通信算法，通过 Channel 执行通信任务并发布完成状态 |
| Channel | 确定跨 rank 通信对端、通信路径和远端内存访问关系 |

图中展示了 Host 启动通信任务、AI Core 通信客户端提交请求、代理介质传递任务信息和状态，以及通信服务端完成数据传输并返回完成状态的过程。一次通信任务按照以下阶段执行：

1. **初始化**：Host 准备通信资源，启动通信服务端和 AI Core Kernel；AI Core 通信客户端完成本轮执行所需的初始化。
2. **Prepare**：AI Core 准备通信请求，记录通信操作、数据位置和数据量等信息，形成任务描述。任务在 Commit 阶段进入可执行状态。
3. **Commit**：AI Core 完成源数据生产以及必要的核间同步后，提交任务执行条件。Commit 表示源数据已经准备完成，通信服务端可以开始处理请求。Commit 完成后，AI Core 继续执行后续计算，通信完成状态由后续的 Wait 确认。
4. **服务端执行**：通信服务端读取任务描述，根据其中的信息完成本端与对端之间的数据传输。数据传输完成后，通信服务端向 AI Core 返回完成状态。
5. **Wait**：AI Core 等待并确认任务完成。Wait 完成表示本轮数据传输已经结束，AI Core 可以读取通信结果；相关数据使用结束后，源内存和目的内存可以复用。
6. **结束**：当前 Kernel 中的通信任务全部完成后，AI Core 通信客户端通知通信服务端结束本轮执行。

代理模式将通信任务交给独立的通信服务端执行，使通信服务端与 AI Core 可以分别执行通信和计算，为通算融合提供了并行执行基础。通算融合算子可以根据数据依赖关系安排通信和计算，一种典型编排如下所示：

**图2** 代理模式下的通算融合编排

![](./figures/proxy_execution_parallel.png "代理模式下的通算融合编排")

在这种编排中，Commit 发布任务执行条件后，通信服务端开始从源内存读取本轮数据并将通信结果写入目的内存，AI Core 继续使用其他数据区域执行与本轮通信没有数据依赖的计算。AI Core 在首次需要使用通信结果的位置执行 Wait；Wait 完成后，目的内存中的通信结果可以用于后续计算。通过将独立计算安排在 Commit 与 Wait 之间，通算融合算子可以重叠通信与计算的执行时间。
