# 代理模式概述

## 代理模式

代理模式将通信任务的发起方与执行方分离。AI Core 作为通信客户端准备和发布通信任务，AICPU_TS 或 CCU 作为通信服务端展开并执行通信任务，再将完成状态反馈给 AI Core。客户端与服务端通过代理介质传递任务参数和执行状态，通过 Channel 对应的通信通路传输跨 rank 用户数据。

通信服务端可以在 AI Core 执行计算时推进已经发布的通信任务。AI Core 需要使用通信结果时，通过任务标识等待对应通信完成。这种执行方式支持在同一个算子中按照数据依赖统一编排计算与通信，形成通算融合流水。

通算融合通常将数据划分为多个可以独立处理的分片，并根据数据依赖组织以下两类流水：

- 通信产生数据、计算消费数据：典型场景包括 AllGather + MatMul。AI Core 发布通信任务后计算本端已有的数据，每个完成的通信分片立即进入计算，形成分片级通信计算流水。
- 计算产生数据、通信消费数据：典型场景包括 MatMul + ReduceScatter。AI Core 提前准备通信任务，每个计算分片完成并经过必要的核间同步后，发布对应的通信任务，然后继续计算下一个分片。

通算融合可以使通信与可并行的计算重叠，减少 AI Core 和通信服务端的空闲时间；计算结果可以尽早进入通信，通信结果也可以尽早进入计算，从而缩短算子的串行关键路径。将计算和通信编排在同一个算子执行过程中，还可以减少 Host 侧的算子启动和中间同步开销。
