# 通信方式分类及选择

在大规模分布式训练和推理业务中，通信方式会同时影响通信时延、带宽利用率、计算资源占用和组网范围。本节面向Ascend 950PR/Ascend 950DT，从驱动模式、通信引擎和通信协议三个相互关联的维度进行选择：驱动模式决定通信操作由当前Kernel直接发起，还是交由独立单元推进；通信引擎决定由哪类硬件执行通信任务；通信协议决定数据采用何种访问语义和互联通路到达对端。实际使用时，需要结合消息大小、性能目标、计算资源占用和系统拓扑综合选择。

## 直驱模式与代理模式

驱动模式描述当前算子Kernel与通信操作之间的发起关系，主要区别在于通信是否由当前Kernel直接执行。该选择会影响通信发起开销、计算资源占用以及通信与计算的并行方式。直驱模式侧重缩短发起路径，代理模式侧重将通信推进过程与当前Kernel解耦，对比结果如下：

**表1** 直驱模式与代理模式对比

| 模式 | 含义 | 主要特点 | 适用场景 |
| --- | --- | --- | --- |
| 直驱模式 | 当前算子Kernel直接发起通信操作。 | 发起路径短、时延低，但通信可能占用执行该Kernel的计算资源。 | 小数据低时延通信、细粒度通算融合和高性能定制算子。 |
| 代理模式 | 当前算子Kernel将通信请求交给独立的数据面单元，由其发起并推进通信。 | 可以将通信推进与当前Kernel解耦，但会增加请求转交和调度开销。 | 需要独立推进通信、减少计算核占用或实现较长时间通算并行的场景。 |

## 通信引擎选择

确定通信的发起方式后，还需要回答“谁执行通信”，即选择实际承接通信任务的硬件主体。AI CPU+TS、AIV和CCU在调度开销、计算核占用、访存开销和适用消息规模方面各有侧重，因此通信引擎的选择应与时延、带宽和资源占用目标匹配。编程接口使用`CommEngine`枚举类型表示通信引擎，各引擎的枚举值和适用场景如下：

**表2** 不同通信引擎的适用场景

| 通信引擎 | 枚举值 | 优势 | 约束 | 适用场景 |
| --- | --- | --- | --- | --- |
| AI CPU+TS | `COMM_ENGINE_AICPU_TS` | 不占用计算核，通信效率高，适用于大数据高带宽场景。 | 通信静态开销较大，对小数据量通信场景不友好。 | 高带宽通信场景 |
| AIV | `COMM_ENGINE_AIV` | 低时延。 | 通信占用Vector计算核，需要多个Vector计算核才能打满通信带宽；通信算子与计算算子竞争计算核资源，可能互相影响。 | 低时延通信场景 |
| CCU | `COMM_ENGINE_CCU` |减少访存带宽与计算核占用。<br>高带宽，低时延。 | 受限于片上资源，支持的通信域数量有限。 | 高带宽、低时延通信场景 |

## 通信协议选择

确定驱动模式和通信引擎后，还需要根据通信操作的编程方式和实际组网选择通信协议。选择时，首先确认所选通信引擎支持哪些协议，即“由谁执行”；然后明确通过网络语义还是内存语义访问远端内存，即“如何通信”；最后结合实际组网确认协议能否覆盖目标通信范围，即“能够到哪里”。Ascend 950PR/Ascend 950DT当前使用的协议包括URMA CTP、URMA TP、UB Memory、UBoE和RoCE，各协议在硬件架构和编程接口中的对应关系如下：

**表3** 通信协议与编程枚举的对应关系

| 通信协议 | 含义 | 枚举值 |
| --- | --- | --- |
| URMA CTP | Compact Transport，Unified Bus 的轻量级传输层模式，借助下层协议共同提供可靠和拥塞控制的传输服务。 | `COMM_PROTOCOL_UBC_CTP` |
| URMA TP（RTP模式） | Reliable Transport，UB（Unified Bus）的标准可靠传输层模式，提供端到端可靠传输服务。 | `COMM_PROTOCOL_UBC_TP` |
| UB Memory | Unified Bus 提供的同步访存语义，支持 Load/Store 操作。 | `COMM_PROTOCOL_UB_MEM` |
| UBoE | UB over Ethernet，UB提供的对接Ethernet的协议接口，可以利用Ethernet交换机扩展UB组网。 | `COMM_PROTOCOL_UBOE` |
| RoCE | RDMA over Converged Ethernet，在Ethernet网络上承载RDMA远端内存访问，需要通过外置网卡接入Ethernet网络。 | `COMM_PROTOCOL_ROCE` |

其中，URMA（UB Remote Memory Access）是灵衢互联（Unified Bus，UB）提供的异步远端内存访问能力，URMA CTP和URMA TP是其两种传输模式。编程接口使用`CommProtocol`枚举类型表示所选通信协议。枚举值存在不代表所有通信引擎和数据面接口都支持该协议，还需要结合通信引擎支持关系和具体接口约束进行选择。

### 支持的通信引擎

通信协议必须与执行通信任务的硬件引擎匹配：

**表4** 通信协议与通信引擎

| 通信引擎 | 支持的通信协议 |
| --- | --- |
| AIV | URMA CTP、URMA TP、UB Memory、RoCE |
| AI CPU+TS | URMA CTP、URMA TP、UB Memory、UBoE、RoCE |
| CCU | URMA CTP、URMA TP |

### 远端内存访问方式

通信协议访问远端内存的方式可以分为网络语义和内存语义。两种语义的核心对象、操作方式和通信模型如下：

**表5** 远端内存访问方式

| 访问语义 | 核心对象 | 操作方式 | 通信模型 | 适用协议 |
| --- | --- | --- | --- | --- |
| 网络语义 | Channel（通信通道） | 基于Channel执行Write、Read和Notify等操作。 | 支持单边操作，也支持需要两端配合的双边操作。 | URMA CTP、URMA TP、UBoE、RoCE |
| 内存语义 | 通信设备 + 映射内存 | 把远端内存映射到本地地址空间，用本地拷贝访问。 | 单边操作，只需一端发起。 | UB Memory |

### 通信范围

通信范围由协议能力和实际组网共同决定。为避免范围重叠，表6中的卡内是指同一NPU内部，卡间是指同一机柜内不同NPU之间，机柜间是指通信两端位于不同机柜。选择协议时，可以先根据目标通信范围进行筛选，再确认本端与对端之间存在相应的Endpoint和可达链路。

**表6** 通信协议的通信范围

| 通信范围 | 可选通信协议 |
| --- | --- |
| 卡内 | URMA CTP、URMA TP、UB Memory |
| 卡间 | URMA CTP、URMA TP、UB Memory、UBoE、RoCE |
| 机柜间 | UBoE、RoCE；URMA CTP、URMA TP、UB Memory（跨机柜UB网络可达时） |
