# Asccomm AIV RoCE write_nbi/read_nbi MPI Sample

## Overview

This sample calls the Asccomm RoCE interfaces directly in an Ascend C AIV kernel, covering init, write_nbi, read_nbi, commit, drain, lock, and unlock. MPI manages the multiple host processes. Each process initializes the HCCL communicator, registers communication memory, creates a RoCE P2P channel, and validates the data after the kernel completes.

## Supported Products and CANN Software Versions

| Product | CANN Software Version |
|---------|-----------------------|

## Behavior

Rank i communicates with rank i + N/2, where N is the total rank count:

- 2 ranks: rank 0 ↔ rank 1
- 4 ranks: rank 0 ↔ rank 2, rank 1 ↔ rank 3
- 8 ranks: rank 0 ↔ rank 4, rank 1 ↔ rank 5, rank 2 ↔ rank 6, rank 3 ↔ rank 7

Each rank creates only its channel to the unique peer. The kernel calls the interfaces in this order:

```cpp
asccomm.init(...);                   // Initialize the Asccomm UB workspace
asccomm.lock(channel);               // Acquire the channel lock
asccomm.write_nbi<false>(...);       // Post a deferred RoCE WRITE
asccomm.read_nbi<false>(...);       // Post a deferred RoCE READ
asccomm.commit<PIPE_S>(channel);     // Trigger the doorbell once
asccomm.unlock(channel);            // Flush channel counters and release the lock
asccomm.drain<PIPE_MTE3>(channel);  // Wait for CQE completion
```

The communication buffer has three segments: seg0 stores the local source, seg1 receives data written by the peer, and seg2 stores data read back from the peer. After the kernel, the host validates the rank pattern in both result segments byte by byte.

## Data Layout

Each rank registers a 4096-byte communication buffer. The first 768 bytes are used for validation:

| Offset | Size | Purpose |
| --- | ---: | --- |
| `[0, 256)` | 256B | Source data owned by this rank |
| `[256, 512)` | 256B | `write_nbi` result from the peer |
| `[512, 768)` | 256B | Data read back from the peer |

The kernel's Asccomm workspace is 512 bytes in VECOUT UB.

## Build

Configure the CANN environment, then build in this directory:

```bash
cd examples/aicore/asccomm/07_asccomm_roce_normal_write_read
source ${install_path}/cann/set_env.sh
export MPI_HOME=/usr/local/mpich
mkdir build
cd build
cmake -DCMAKE_ASC_ARCHITECTURES=dav-3510 ..
make -j
```

To enable `ASCENDC_DEBUG`, use `cmake -DCMAKE_ASC_ARCHITECTURES=dav-3510 -DASCENDC_DEBUG=ON ..`.

The RoCE backend is selected with the `ASCCOMM_ROCE_BACKEND_MLX5` CMake option: when the option is disabled, the default 1825 NIC is used; when the option is enabled, the mlx5 NIC is used. The option is enabled by default and can be set explicitly with `-DASCCOMM_ROCE_BACKEND_MLX5=OFF` or `-DASCCOMM_ROCE_BACKEND_MLX5=ON`.

## Enable MPI Environment Variables

Adjust the following settings according to the actual MPI installation path.

```bash
export MPI_HOME=/usr/local/mpich
export PATH="${MPI_HOME}/bin:${PATH}"
export LD_LIBRARY_PATH="${MPI_HOME}/lib:${LD_LIBRARY_PATH:-}"
```

## Run

Start the sample with MPI. The rank count must be an even number greater than or equal to 2:

```bash
cd examples/aicore/asccomm/07_asccomm_roce_normal_write_read
source ${install_path}/cann/set_env.sh
mpirun -n 4 $(pwd)/build/asccomm_roce_normal_write_read
```

A successful run prints:

```text
[rank 0] asccomm_roce_normal_write_read | peer=2 | PASS
[rank 1] asccomm_roce_normal_write_read | peer=3 | PASS
[rank 2] asccomm_roce_normal_write_read | peer=0 | PASS
[rank 3] asccomm_roce_normal_write_read | peer=1 | PASS
RESULT | Example=asccomm_roce_normal_write_read | Status=PASS
```

## Notes

- Running the sample requires at least two NPUs; the rank count must be even and must not exceed the available NPU count.
- The channel must use COMM_PROTOCOL_ROCE, matching `asc::asccomm<asc::COMM_PROTOCOL_ROCE>` on the kernel side.
- MPI Bcast distributes the root info generated by HcclGetRootInfo to all ranks.
- write_nbi and read_nbi are posted with commit=false, so commit is required. Data is validated only after drain returns.
- Each rank creates a channel only to rank i + N/2, and both result segments use that peer's pattern.
