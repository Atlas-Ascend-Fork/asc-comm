# Hcomm AIV RoCE WriteNbi/ReadNbi MPI Sample

## Overview

This sample calls the Hcomm RoCE interfaces directly in an Ascend C AIV kernel, covering Init, WriteNbi, ReadNbi, Commit, Drain, Lock, and Unlock. MPI manages the multiple host processes. Each process initializes the HCCL communicator, registers communication memory, creates a RoCE P2P channel, and validates the data after the kernel completes.

## Supported Products and CANN Software Versions

| Product | CANN Software Version |
|---------|-----------------------|

## Behavior

Rank i communicates with rank i + N/2, where N is the total rank count:

- 2 ranks: rank 0 ↔ rank 1
- 4 ranks: rank 0 ↔ rank 2, rank 1 ↔ rank 3
- 8 ranks: rank 0 ↔ rank 4, rank 1 ↔ rank 5, rank 2 ↔ rank 6, rank 3 ↔ rank 7

Each rank creates only its channel to the unique peer. The kernel calls the interfaces in this order:

```cpp
hcomm.Init(...);            // Initialize the Hcomm UB workspace
hcomm.Lock(channel);        // Acquire the channel lock
hcomm.WriteNbi<false>(...); // Post a deferred RoCE WRITE
hcomm.ReadNbi<false>(...);  // Post a deferred RoCE READ
hcomm.Commit(channel);      // Trigger the doorbell once
hcomm.Unlock(channel);      // Flush channel counters and release the lock
hcomm.Drain(channel);       // Wait for CQE completion
```

The communication buffer has three segments: seg0 stores the local source, seg1 receives data written by the peer, and seg2 stores data read back from the peer. After the kernel, the host validates the rank pattern in both result segments byte by byte.

## Data Layout

Each rank registers a 4096-byte communication buffer. The first 768 bytes are used for validation:

| Offset | Size | Purpose |
| --- | ---: | --- |
| `[0, 256)` | 256B | Source data owned by this rank |
| `[256, 512)` | 256B | `WriteNbi` result from the peer |
| `[512, 768)` | 256B | Data read back from the peer |

The kernel's Hcomm workspace is 512 bytes in VECOUT UB.

## Build

Configure the CANN environment, then build in this directory:

```bash
cd examples/aicore/hcomm/07_hcomm_roce_normal_write_read
source ${install_path}/cann/set_env.sh
export MPI_HOME=/usr/local/mpich
mkdir build
cd build
cmake -DCMAKE_ASC_ARCHITECTURES=dav-3510 ..
make -j
```

To enable `ASCENDC_DEBUG`, use `cmake -DCMAKE_ASC_ARCHITECTURES=dav-3510 -DASCENDC_DEBUG=ON ..`.

## Enable MPI Environment Variables

Adjust the following settings according to the actual MPI installation path.

```bash
export MPI_HOME=/usr/local/mpich
export PATH="${MPI_HOME}/bin:${PATH}"
export LD_LIBRARY_PATH="${MPI_HOME}/lib:${LD_LIBRARY_PATH:-}"
```

## Run

Start the sample with MPI. The rank count must be an even number greater than or equal to 2:

```bash
cd examples/aicore/hcomm/07_hcomm_roce_normal_write_read
source ${install_path}/cann/set_env.sh
mpirun -n 4 $(pwd)/build/hcomm_roce_normal_write_read
```

A successful run prints:

```text
[rank 0] hcomm_roce_normal_write_read | peer=2 | PASS
[rank 1] hcomm_roce_normal_write_read | peer=3 | PASS
[rank 2] hcomm_roce_normal_write_read | peer=0 | PASS
[rank 3] hcomm_roce_normal_write_read | peer=1 | PASS
RESULT | Example=hcomm_roce_normal_write_read | Status=PASS
```

## Notes

- Running the sample requires at least two NPUs; the rank count must be even and must not exceed the available NPU count.
- The channel must use COMM_PROTOCOL_ROCE, matching `Hcomm<COMM_PROTOCOL_ROCE>` on the kernel side.
- MPI Bcast distributes the root info generated by HcclGetRootInfo to all ranks.
- WriteNbi and ReadNbi are posted with commit=false, so Commit is required. Data is validated only after Drain returns.
- Each rank creates a channel only to rank i + N/2, and both result segments use that peer's pattern.
